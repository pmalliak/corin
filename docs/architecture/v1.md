# V1 Architecture

Status: proposed for review on 2026-08-31.  
Scope: V1 interactive coach, with implementation initially limited to the status vertical slice in [`../plans/vertical-slice-1.md`](../plans/vertical-slice-1.md).

## Recommended stack

| Area | Choice | Why |
| --- | --- | --- |
| Control plane | TypeScript, Cloudflare Workers, Hono | Small HTTP surface for Discord interactions, pairing, and health. |
| Persistent identity | Cloudflare D1 (SQLite) | Relational user/device/pairing model with low operational overhead. |
| Live device presence/state | One Durable Object per device, hibernating WebSocket API | Single-writer coordination for each connected agent; no permanent game history. |
| Secrets | Cloudflare Worker secrets | Discord token/public key and OpenAI key stay off devices. |
| Discord control UI | Discord interactions/slash commands verified at the Worker | Discord user ID is the V1 identity. |
| Local agent | Rust binary, `reqwest` + `tokio-tungstenite`; Windows packaging later | Small native agent; same binary runs a fixture provider on macOS. |
| Contract validation | TypeScript Zod schemas exported as JSON Schema; Rust generated/handwritten types | One versioned boundary between agent and control plane. |
| Tests | Vitest (Worker/contracts), Rust unit/integration tests, Miniflare/Wrangler local tests | Fast contract and state-machine coverage. |
| V2/V3 voice service | Node.js/TypeScript, `discord.js` + `@discordjs/voice`, container/VPS | Required for Discord voice UDP media; deliberately outside Worker runtime. |
| AI voice (after slice) | OpenAI Realtime API, server-owned connection and controlled tool calls | Native speech-to-speech and tool calling; never direct access to a device. |

## Deployment boundary

```text
Discord interaction HTTP ───────┐
Local agent ── outbound WSS ────┼── Cloudflare Worker ── D1
                                │          │
                                │          └── DeviceSession Durable Object
                                │                    └── latest normalized state
                                │
Discord voice UDP/WebSocket ────┴── later: persistent Node Voice Bridge
                                           │
                                           └── OpenAI Realtime + controlled tools
```

Cloudflare is the server/control-plane platform. The later Voice Bridge must run in a UDP-capable container or VM and uses the Cloudflare API/control plane; it is not an alternate database or business-logic owner.

## Runtime responsibilities

### Worker

- Verify Discord interaction signatures and authorize guild/user requests.
- Create single-use, short-lived pairing codes.
- Route authenticated device WebSocket upgrades to its DeviceSession Durable Object.
- Serve `/coach status` from persistent device metadata plus the latest ephemeral session status.
- Apply input validation, rate limits, audit-safe structured logs, and correlation IDs.

### D1

Persist only identity and revocation data:

- `users`: internal ID, Discord user ID (unique), timestamps.
- `devices`: internal ID, owner user ID, display name, credential record, timestamps, revocation timestamp.
- `pairing_codes`: hashed code, intended Discord user ID, expiry, consumption metadata.

Do not persist live game snapshots in V1.

### DeviceSession Durable Object

- Authenticate an outbound agent connection after the Worker upgrade gate.
- Hold/restore only connection metadata and the most recent normalized status/state.
- Mark the device offline on socket close and expose a narrow RPC/read API to the Worker.
- Treat state as expired if no heartbeat arrives within its explicit TTL.

Durable Object hibernation means no correctness may depend solely on JavaScript memory. The WebSocket attachment contains only small non-secret connection metadata; durable identity remains in D1.

### Local agent

- Poll a `GameDataProvider` at a conservative, configurable cadence.
- Normalize only status fields for the first slice, then the permitted game-state schema.
- Maintain one outbound WSS connection and reconnect with exponential backoff plus jitter.
- Store its long-lived credential in the OS credential store; never log it.
- Contain no Discord, OpenAI, or Riot Web API credentials.

### Future Voice Bridge

- Maintain Discord Gateway/voice connections, receive only the requesting speaker’s Opus stream, and play coach audio.
- Associate a PTT activation with a Discord user ID before forwarding that user’s audio.
- Own OpenAI Realtime sessions and provide only backend-enforced tools such as `get_current_player_state`.

## Pairing and authentication

1. `/coach connect` creates a random, single-use code with a short expiry and stores only its hash.
2. The agent exchanges the code over TLS for a newly created device credential.
3. Store the credential as an opaque random bearer secret in the OS credential store; store only a keyed hash/server-side verifier in D1.
4. Every device connection proves its credential during the WebSocket upgrade; the Worker resolves it to exactly one device and owner.
5. Device revocation immediately rejects future connections and closes an active session where practical.

The first slice does not need refresh-token complexity. Credential rotation is a later hardening task; revocation and re-pairing are required from the start.

## Game-data boundary

The real provider calls only `https://127.0.0.1:2999` while a game is active. The client uses Riot’s supplied root certificate where feasible; development may explicitly allow the local self-signed certificate only for this loopback origin. No general TLS bypass is acceptable.

Provider interface:

```text
GameDataProvider
  getStatus() -> AgentGameStatus
  getCurrentGame() -> NormalizedGameState | NoActiveGame
```

`RealLiveClientProvider` obtains only documented, minimal endpoints. `FixtureGameDataProvider` implements the identical interface from deterministic JSON fixtures. The agent switches provider through an explicit development configuration, never a runtime guess.

## Push-to-talk decision

Use a local-agent global hotkey in the later voice phase. It emits authenticated `ptt.started` and `ptt.stopped` events for its paired Discord owner. The Voice Bridge accepts voice packets only for that owner and activation window. Discord’s native PTT is not a coach-request signal and cannot establish this intent by itself.

## Security invariants

- A Discord speaker can read only the latest state owned by their mapped device.
- Agent traffic is outbound TLS/WSS only; port 2999 is never exposed.
- Raw League responses and arbitrary agent-supplied fields never reach an LLM.
- Pairing codes and device credentials are hashed/verifiable at rest, expire or revoke, and are never logged.
- Discord and OpenAI secrets remain server-side.
- All external messages are schema-validated and rate-limited before state mutation.

## Current constraints and verification gates

| Topic | Known constraint | Before implementation |
| --- | --- | --- |
| Discord voice | Voice media uses a separate voice WebSocket plus UDP; Workers cannot be the media runtime. | Prove a Node Voice Bridge can join, receive one selected user’s Opus, and play a generated Opus response. |
| Discord PTT | No bot-native event proves a native Discord PTT press was intended for the coach. | Prototype local hotkey → signed PTT event → selected-speaker audio gate. |
| OpenAI Realtime | Realtime supports audio, WebRTC/WebSocket/SIP, and function calling; limits/model availability are account-tier dependent. | Run a one-user tool-call and interruption latency/cost spike with the intended account. |
| Cloudflare | Durable Objects are suitable for incoming long-lived WSS and hibernation resets memory. | Test authentication, reconnect, attachment recovery, and TTL behavior with a real Worker deployment. |
| Riot Live Client API | It is local HTTPS with a self-signed certificate; endpoint/schema behavior may patch-change. | Pin fixture payloads from the documented OpenAPI endpoint and run a Windows real-client compatibility smoke test. |
| Riot policy | Riot asks developers to declare Game Client API endpoint usage. | Confirm developer-portal registration/disclosure and applicable policy before distributing the agent. |

## Sources checked

- [Riot Game Client API](https://developer.riotgames.com/docs/lol) documents the local HTTPS API, self-signed certificate, OpenAPI specification, and relevant live endpoints.
- [Cloudflare Durable Object WebSockets](https://developers.cloudflare.com/durable-objects/best-practices/websockets/) documents hibernating inbound WebSockets and memory reset behavior.
- [Cloudflare Workers TCP sockets](https://developers.cloudflare.com/workers/runtime-apis/tcp-sockets/) documents TCP support; Worker protocol support does not provide the UDP media transport Discord voice requires.
- [Discord voice connections](https://docs.discord.com/developers/topics/voice-connections) documents the distinct voice WebSocket and UDP IP/port handshake.
- [discord.js VoiceReceiver](https://discordjs.dev/docs/packages/voice/main/VoiceReceiver:Class) documents selected-user Opus receive streams.
- [Official OpenAI Realtime model documentation](https://developers.openai.com/api/docs/models/gpt-realtime) documents current audio/text support and function calling. OpenAI Docs informed the Realtime recommendation.
